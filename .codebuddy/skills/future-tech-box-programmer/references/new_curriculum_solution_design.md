# 未来科技盒 · 新课标方案设计参考（2.0 版）

> 本文件为 SKILL 的「方案生成模式」提供参考依据。
> 课标来源：《义务教育信息科技课程标准（2022年版2025年修订）》（2025版新课标，义务教育信息科技）。
> 用途：当教师提出「如何用未来科技盒做某某方案/作品」时，按本文件结构与课标要点生成符合规范的项目方案。
> 注意：本文件只描述「方案设计」，不含代码。用户确认方案后，SKILL 再进入「需求→代码→编译→烧录」主流程。
> ⚠️ 本文件针对 2.0 硬件（XIAO ESP32S3）。3.0 硬件差异见 3.0 skill 的 `new_curriculum_solution_design.md`。

## 一、课标核心素养速查（写方案目标/评价时取用）

义务教育信息科技课程核心素养四维，四个方面互相支持、互相渗透：

| 素养维度 | 内涵要点（节选课标原文精神） |
|----------|------------------------------|
| 信息意识 | 对信息的敏感度和价值判断力；评估数据来源、辨别数据可靠性与时效性；数据安全意识；自主动手解决问题的意识 |
| 计算思维 | 问题解决中的抽象、分解、建模、算法设计；通过模拟/仿真验证方案，反思优化并迁移 |
| 数字化学习与创新 | 选用合适的数字设备、平台和资源管理学习过程；开展探究性学习；创造性解决问题、设计和创作个性化作品 |
| 信息社会责任 | 信息社会中的文化修养、道德规范和行为自律；保护个人/他人隐私；尊重知识产权；安全使用数字设备 |

## 二、内容模块与学段定位（判断方案适合哪个学段）

课标以「数据、算法、网络、信息处理、信息安全、人工智能」为六条逻辑主线，按学段螺旋进阶。与未来科技盒（ESP32-S3 智能硬件）关联度最高的学段与模块如下：

| 学段 | 内容模块 | 与未来科技盒的契合点 | 方案建议定位 |
|------|----------|----------------------|--------------|
| 第一学段（1～2年级） | 信息交流与分享、信息隐私与安全、数字设备体验 | 不编程，纯体验/观察 | 通常不推荐直接进入硬件方案；可作为「数字设备体验」的观察对象 |
| 第二学段（3～4年级） | 在线学习与生活、数据与编码、跨学科「数据编码探秘」 | 用 LED 矩阵呈现编码与数据；按键输入 | 简单「输入-输出」型方案，如「灯光密码」「红绿灯模拟」 |
| 第三学段（5～6年级） | 身边的算法、过程与控制、跨学科「小型系统模拟」 | ⭐ 最契合：输入-计算-输出系统、反馈、顺序/分支/循环、通过编程验证 | 首选学段，如智能红绿灯、循迹小车、超声波避障 |
| 第四学段（7～9年级） | 互联网应用与创新、物联网实践与探索、人工智能与智慧社会、跨学科「互联智能设计」 | ⭐ WiFi 联网、传感器数据采集/传输/反馈、ASR Pro 语音交互 | 高进阶方案，如智能家居物联系统、语音控制小车 |

> 原则：教师未说明学段时，默认推荐 5～6 年级（第三学段）或 7～9 年级（第四学段），并说明选择理由；若教师指定学段，严格按该学段目标降/升难度。

## 三、与未来科技盒 2.0 硬件能力映射（方案选型的唯一依据，不得虚构硬件）

### 3.1 输入类（传感器/交互）
| 模块 | 型号/方式 | 引脚/接口 | 课标对应 |
|------|-----------|-----------|----------|
| 按键 KEY_A / KEY_B | 内部上拉，按下 LOW | KEY_A=GPIO21，KEY_B=GPIO0(兼BOOT) | 输入环节 |
| 超声波测距 | 接口2 | SIG=GPIO7 | 数据采集、避障 |
| 循迹传感器 | 2.0：左=GPIO2/右=GPIO1（接口3） | ⚠️ 与 3.0 不同（3.0 为 GPIO3/GPIO4） | 分支判断、反馈 |
| 三轴加速度计 | LIS3DHTR，I2C 地址 0x18 | I2C1：SDA=GPIO39/SCL=GPIO40 | 数据采集、姿态判断 |
| 颜色传感器 | VEML6040，I2C 地址 0x10 | I2C1 | 数据采集、分类识别 |
| 温湿度传感器 | DHT20，I2C 地址 0x38 | I2C1 | 物联网数据采集 |
| PS2 手柄 | Arduino-PS2X-ESP32 | CLK=41,CMD=9,CS=42,DAT=10 | 人机交互输入 |
| 语音模块 | ASR Pro（预刷程序，串口通讯控制） | 串口通讯，无需编程 | 语音交互 |
| WiFi | STA/AP 模式 | 内置 | 互联网/物联网（网页遥控） |

### 3.2 输出类（执行器/显示）
| 模块 | 方式 | 引脚/接口 | 课标对应 |
|------|------|-----------|----------|
| LED 矩阵 | 9 个单色，行列扫描（需 scanDisplay 维持显示） | GPIO33-38 | 输出、编码呈现、可视化 |
| 蜂鸣器 | 板载 | GPIO26 | 声音反馈 |
| 电机 M1-M4 | 4 路 GPIO11-18，可组小车/麦克纳姆轮 | GPIO11-18 | 执行机构 |
| 舵机 S1/S2 | 云台 | GPIO47/48 | 执行机构 |
| LED Bar 灯条 | Grove | Grove 接口 | 数据可视化 |

### 3.3 ⚠️ 接口限制（方案必须合规，违反则方案不可实现）
- 2.0 LED 矩阵为单色行列扫描，需要持续调用 `scanDisplay()` 维持显示，loop() 中不宜用 `delay()`；方案中的「显示反馈」需按此特性设计（可配合非阻塞方式）。
- 2.0 循迹传感器引脚为 GPIO2/GPIO1（与 3.0 的 GPIO3/GPIO4 不同），方案中需注明版本。
- 蜂鸣器 GPIO26 在 2.0 为板载可用（3.0 中该引脚变为 Grove 接口4，待确认）。
- 语音模块 ASR Pro 已预刷程序，方案中「语音控制」只需在 ESP32 端编写串口接收/解析，不虚构自定义语音协议。

## 五、方案取舍原则（技术克制 + 特色优先，核心）

> 本原则是方案设计的「第一准则」。方案的价值不在堆技术，而在**有特色、有风格、有趣味、可落地**。生成方案时必须遵守以下取舍。

### 5.1 技术克制（不过度拓展高难度功能）
- **默认只用低难度、已验证、易采买的模块**：按键、LED 矩阵、蜂鸣器、超声波、循迹、温湿度、加速度计、颜色传感器、电机、舵机、PS2 手柄、WiFi Web 遥控。
- **不主动引导高难度/高风险模块**：如 GPS/TWD 定位、基站定位、云平台大屏、多机协同、复杂 AI 模型等。**除非用户明确要求**，否则不写进方案主体。
- **用户未要求时**：方案默认「基础可落地版」即可；高难度扩展仅在末尾作为「可选进阶（需用户确认）」一句话提及，不展开、不占用主流程。
- **用户明确要求时**：可补充进阶功能，但必须**标注落地风险**——采买难度、接线复杂度、供电电压要求、是否需额外器件（如 GPS 需 3.3V/天线、定位模块需空旷环境），并给出替代简化建议。
- **示例**：做「捉迷藏」游戏方案时，默认用「按键/超声波/亮度判断 + LED 矩阵反馈 + 蜂鸣器」实现捉迷藏玩法；不要默认引导 TWD 定位、GPS 追踪等高难度功能。

### 5.2 特色与风格优先
方案的「灵魂」在于特色与趣味，优先设计：
- **地区/文化特色**：结合本地风土、非遗、民俗、红色文化、校园文化等（如用未来科技盒做一个介绍本地特色的小车/装置）
- **主题风格**：童话、科幻、国风、机甲、宠物、闯关等，统一贯穿名称、玩法、场景、灯光
- **游戏化玩法**：计分、关卡、倒计时、角色扮演、合作/对抗、奖励反馈（灯光/声音/震动）等，让作品"好玩"
- **趣味呈现**：用灯光动效、声音、剧情旁白营造氛围

### 5.3 技术实现可落地
- 技术实现严格按用户描述要求提供；用户没提的，选**最简单、最不易出错**的实现路径。
- 涉及接线/供电不确定的器件（如继电器水泵、GPS、直流大功率电机），方案中明确标注"需教师确认接线与供电"，不假设默认可用。
- 优先提供"用现有板载模块即可实现"的版本，把外接器件降到最少。

### 5.4 方案主次结构
一个完整方案 = **主线（基础可落地玩法 + 特色/风格/趣味）** + **支线（可选进阶功能，用户要求才展开）**。主线必须完整可执行；支线不影响主线的完整性。

## 六、示例方案（循迹小车，供参照写法，不直接输出此例）

**作品名称**：循迹小车
**适用学段**：5～6 年级（第三学段「过程与控制」+「身边的算法」）
**驱动问题**：快递分拣中心的小车如何沿着线路自动送货？我们能不能用未来科技盒做一个能沿黑线行驶的小车？

**核心素养目标**（节选）：
1. 能描述循迹小车的输入（循迹传感器）、计算（判断左/右/直行）、输出（电机动作）过程（计算思维）
2. 能设计"黑线检测→分支判断→电机控制"的算法并用流程图表达（计算思维）
3. 能合理选用传感器并解释数据判断的依据（信息意识）

**硬件选型**：循迹传感器（接口3：左=GPIO2/右=GPIO1）+ 电机 M1-M4（GPIO11-18）+ 蜂鸣器（GPIO26，过线提示）。

**系统架构**：循迹输入 → 主控判断（分支）→ 电机输出（反馈闭环）。

**教学过程要点**：情境导入（快递分拣）→ 抽象分解（输入/判断/输出）→ 搭建编程 → 测试调阈值 → 拓展（增加超声波避障/PS2 遥控切换）。

**非接线创客内容**：用瓦楞纸做小车车身与"货厢"，KT 板做城市道路/轨道场景，增强展示效果。

## 七、示例方案（捉迷藏·校园寻宝，体现"技术克制 + 游戏化"）

> 本示例专门演示：即使主题容易引导到"定位"类高难度功能，方案也要克制，回归特色 + 玩法。

**作品名称**：校园捉迷藏·灯光信号寻宝
**适用学段**：5～6 年级（第三学段「过程与控制」）
**主题风格**：童话探险（如"森林精灵的宝藏"）
**游戏化玩法**：一人当"守卫"（手持未来科技盒），其他同学悄悄靠近；守卫按下按钮进入"侦察模式"，超声波/亮度检测到有人靠近时，LED 矩阵变亮 + 蜂鸣器短鸣提示，被"抓到"则扣分。也可反向：寻宝者找到藏在角落的装置，装置用灯语提示距离（近=亮、远=暗/闪烁频率不同）。

**核心素养目标**（节选）：
1. 能描述装置的输入（超声波/按键）、计算（距离阈值判断）、输出（LED 矩阵、蜂鸣器）过程（计算思维）
2. 能设计"距离越近→报警越急"的简单算法并调整阈值（计算思维）
3. 能在游戏中遵守规则、文明使用装置（信息社会责任）

**硬件选型**（全部为低难度易落地模块）：
| 模块 | 引脚 | 作用 |
|------|------|------|
| 超声波传感器 | 接口2 GPIO7 | 检测"有人靠近" |
| LED 矩阵 | GPIO33-38 | 距离提示（亮度/闪烁） |
| 蜂鸣器 | GPIO26 | 被抓提示音 |
| 按键 KEY_A | GPIO21 | 守卫启动/停止 |

**系统架构**：超声波输入 → 主控阈值判断 → LED 矩阵 + 蜂鸣器输出（反馈）。

**可选进阶（仅用户明确要求才展开）**：若用户要求"远程追踪被找者"，可提及 TWD 定位/GPS 作为进阶方向，但必须标注：需额外定位模块与天线、供电要求、空旷环境限制、采买与接线复杂度高，建议先用"灯语距离提示"实现核心玩法。

**非接线创客内容**：用瓦楞纸/卡纸做"宝藏盒"外观与掩体；KT 板做校园地图场景；热熔胶固定传感器支架。
